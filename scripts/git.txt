GIT + GITHUB + GITHUB PAGES
Краткая шпаргалка для проекта R / Quarto


0. ГЛАВНАЯ ИДЕЯ
----------------

Git — система контроля версий на вашем компьютере.
GitHub — сайт, на котором хранится удаленная копия проекта.
Репозиторий — папка проекта, за изменениями в которой следит Git.
Коммит — сохраненный «снимок» проекта с кратким описанием изменений.

Рабочий цикл:

  *получить чужие изменения → изменить файлы → проверить →
  добавить → сделать коммит → отправить на GitHub


1. УСТАНОВКА И ОДНОРАЗОВАЯ НАСТРОЙКА
------------------------------------

Скачать Git: https://git-scm.com/downloads

# Проверить установку
git --version

# Указать автора будущих коммитов
git config --global user.name "Имя Фамилия"
git config --global user.email "your_email@example.com"

# Новые репозитории будут начинаться с ветки main
git config --global init.defaultBranch main

# Проверить настройки; для выхода из длинного списка нажмите q
git config --list

Email должен быть добавлен и подтвержден в аккаунте GitHub, иначе коммиты
могут не связываться с вашим профилем.

В RStudio проверьте:

  Tools → Global Options → Git/SVN

Путь к Git должен определиться автоматически. Включите:

  Enable version control interface for RStudio projects


2. ДОСТУП К GITHUB ЧЕРЕЗ SSH
----------------------------

SSH-ключ позволяет отправлять изменения без пароля от GitHub.

В RStudio:

1. Tools → Global Options → Git/SVN → Create SSH Key.
2. Откройте публичный ключ: View public key.
3. Скопируйте его целиком.
4. На GitHub откройте:

     Settings → SSH and GPG keys → New SSH key

5. Вставьте ключ, задайте понятное название и сохраните.

# Проверить соединение
ssh -T git@github.com

При первом подключении подтвердите его, введя yes.


3. СОЗДАТЬ ПРОЕКТ ПОД КОНТРОЛЕМ ВЕРСИЙ
--------------------------------------

ВАРИАНТ А. Новый проект RStudio / Quarto

При создании проекта включите:

  Create a git repository

Это равносильно команде git init.


ВАРИАНТ Б. Уже существующая папка проекта

Откройте терминал в корневой папке проекта и выполните:

# Создать локальный репозиторий
git init

# Проверить файлы
git status

# Добавить все файлы, кроме перечисленных в .gitignore
git add .

# Создать первый коммит
git commit -m "initial commit"

После git init перезапустите проект RStudio: появится вкладка Git.


4. СВЯЗАТЬ ЛОКАЛЬНЫЙ ПРОЕКТ С GITHUB
------------------------------------

1. На GitHub выберите New repository.
2. Задайте короткое имя латиницей.
3. Выберите Public, если используете бесплатный аккаунт и GitHub Pages.
4. НЕ добавляйте README, .gitignore и лицензию: локальный проект уже создан.
5. Нажмите Create repository.
6. Скопируйте SSH-адрес, например:

     git@github.com:USERNAME/PROJECT.git

В терминале проекта выполните:

# Замените адрес своим
git remote add origin git@github.com:USERNAME/PROJECT.git

# Назвать главную ветку main
git branch -M main

# Первая отправка на GitHub и настройка связи веток
git push -u origin main

# Проверить адрес удаленного репозитория
git remote -v


5. ЕСЛИ ПРОЕКТ УЖЕ ЕСТЬ НА GITHUB
---------------------------------

Скопируйте SSH-адрес: Code → Local → SSH.

# Перейти в папку, внутри которой должен появиться проект
cd путь/к/папке

# Скачать репозиторий
git clone git@github.com:USERNAME/PROJECT.git

# Перейти в папку проекта
cd PROJECT

В RStudio тот же результат дает:

  File → New Project → Version Control → Git


6. ОСНОВНОЙ РАБОЧИЙ ЦИКЛ
------------------------

# 1. В начале работы получить изменения с GitHub
git pull

# 2. После редактирования посмотреть состояние проекта
git status

# 3. Посмотреть сами изменения
git diff

# 4. Добавить один файл в будущий коммит
git add index.qmd

# Или добавить все изменения
git add .

# 5. Создать коммит
git commit -m "update home page"

# 6. Отправить коммиты на GitHub
git push

Важно:

* git add отбирает изменения для будущего коммита;
* git commit сохраняет новую версию локально;
* git push отправляет готовые коммиты на GitHub;
* один коммит должен соответствовать одному понятному изменению;
* сообщение коммита должно кратко отвечать на вопрос «что изменилось?».

Вкладка Git в RStudio позволяет выполнить те же действия кнопками:

  Pull → отметить файлы → Commit → Push


7. ИСТОРИЯ И БЕЗОПАСНАЯ ОТМЕНА
------------------------------

# Краткая история коммитов
git log --oneline

# Кто и в каком коммите изменил каждую строку файла
git blame index.qmd

# Убрать файл из будущего коммита, но сохранить правки
git restore --staged index.qmd

# Отменить незакоммиченные правки в файле
# ОСТОРОЖНО: эти правки будут потеряны
git restore index.qmd

Команды git reset --hard и git push --force здесь не рассматриваются:
они могут безвозвратно удалить работу или переписать общую историю.


8. ФАЙЛ .gitignore
------------------

.gitignore перечисляет файлы, которые Git не должен отслеживать.
Он находится в корне проекта и называется именно .gitignore.

Пример:

  .Rhistory
  .RData
  .Ruserdata
  .Rproj.user/
  .quarto/
  .DS_Store

Не публикуйте пароли, токены, API-ключи, персональные данные и большие
исходные датасеты. Если секрет уже попал в коммит, одного удаления файла
недостаточно: ключ нужно немедленно отозвать и заменить.


9. ПОДГОТОВИТЬ САЙТ QUARTO
--------------------------

В файле _quarto.yml укажите папку для готового сайта:

  project:
    type: website
    output-dir: docs

Отступы в YAML важны: type и output-dir должны находиться внутри project.

Один раз создайте в корне проекта пустой файл .nojekyll. Он отключает
дополнительную обработку сайта системой Jekyll на GitHub:

  file.create(".nojekyll")

Эту команду выполните в консоли R. Файл .nojekyll нужно добавить в Git.

Отрендерить сайт можно кнопкой Render Website в RStudio или командой:

  quarto render

Альтернатива из R:

  quarto::quarto_render()

После рендеринга проверьте, что появился файл:

  docs/index.html

В папке docs должны также находиться стили, скрипты, изображения и другие
файлы, необходимые готовому сайту.


10. ОПУБЛИКОВАТЬ QUARTO-САЙТ НА GITHUB PAGES
---------------------------------------------

Сначала отправьте исходники и готовую папку docs на GitHub:

  git status
  git add .
  git commit -m "publish website"
  git push

Затем на странице репозитория:

1. Откройте Settings → Pages.
2. В разделе Build and deployment выберите:

     Source: Deploy from a branch
     Branch: main
     Folder: /docs

3. Нажмите Save.
4. Дождитесь завершения публикации.
5. Нажмите Visit site.

Адрес сайта проекта обычно выглядит так:

  https://USERNAME.github.io/PROJECT/

Например:

  репозиторий: https://github.com/anna/text-project
  сайт:        https://anna.github.io/text-project/

После следующих изменений нужно снова:

  1. отрендерить сайт;
  2. закоммитить измененные исходники и папку docs;
  3. выполнить git push.

Pages обновит сайт автоматически. Иногда публикация занимает до 10 минут.

Если у вас уже есть обычный статический сайт с index.html в корне
репозитория, можно выбрать Folder: / (root), а не /docs.


11. ЕСЛИ САЙТ НЕ ОТКРЫВАЕТСЯ
----------------------------

Проверьте:

[ ] Репозиторий содержит docs/index.html.
[ ] В Settings → Pages выбраны main и /docs.
[ ] Папка docs не исключена в .gitignore.
[ ] Последний коммит с папкой docs появился на GitHub.
[ ] Вкладка Actions не показывает ошибку публикации.
[ ] В адресе сайта есть имя репозитория.
[ ] Названия файлов и пути совпадают, включая регистр букв.

Если открывается старая версия:

1. Подождите несколько минут.
2. Обновите страницу без кеша: Ctrl+Shift+R или Cmd+Shift+R.
3. Проверьте последний запуск во вкладке Actions.


12. МИНИМУМ, КОТОРЫЙ НУЖНО ЗАПОМНИТЬ
------------------------------------

Работа с Git:

  git pull
  # редактируем файлы
  git status
  git add .
  git commit -m "краткое описание"
  git push

Публикация Quarto-сайта:

  output-dir: docs
  → quarto render
  → git add .
  → git commit
  → git push
  → Settings → Pages → main → /docs
